<objective>
Make Layer 2's newly ungated write authority (D-23) safe and accountable.

D-23 removed the directive gate on proactive calendar writes, which raises the stakes on
the two invariants that survived: the write must be idempotent, and it must be recorded.
The idempotency requirement is correctness, not permission — 33-CONTEXT.md spells out the
exact failure: compose succeeds → send fails → D-10 logs nothing → the next occasion
re-composes from the same inputs → a duplicate event on Amit's calendar. The audit
requirement is D-25: nothing Klaus does to Amit's calendar may stay invisible, so the
record is written at action time and explicitly not gated on a send ever happening.

Purpose: without the pre-check, an ungated write path plus a retrying occasion produces
duplicate calendar events. Without the audit record, a write whose disclosure message
never landed is invisible forever.
Output: an idempotency pre-check in the calendar create handler and `ActionLogStore`
writes on all three calendar mutations.
</objective>
