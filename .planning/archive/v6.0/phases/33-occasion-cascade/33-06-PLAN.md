<objective>
Turn the nightly review from an always-fire template into an occasion.

Everything that makes the nightly *the nightly* survives: `nightly_target_date`'s
wind-down date shift, `_ensure_reflection`'s journal guarantee, `_gather_tomorrow`, and
`_plain_text_fallback`. What changes is the middle: `_compose_nightly` — a single-shot
LLM call that always produced a message — is replaced by
`run_occasion_cascade(occasion="nightly")`, which can legitimately decide to stay quiet.

Two write-timing decisions invert the current code (D-05, D-07): the journal and the
tomorrow snapshot are written on **every** run, sent or skipped, because "Klaus perceived
the day" and "Klaus decided to speak" are different facts and the Hub depends on the
first. And the whole thing sits behind `OCCASION_CASCADE` (D-30), with the flag-off path
kept byte-identical so the observation window is a genuine A/B.

Purpose: OCC-01 and SC-1 — silence must be a recordable decision that a human reading the
logs can tell apart from an infra failure.
Output: a cascade-routed `run_nightly` with a `skipped_by_judgment` branch, terminal-status
idempotency for the backstop, and unconditional journal/snapshot writes.
</objective>

    **Split the state write.** Replace the single post-send `_set_state` with two writes:
      - `_set_state(target_date, {"structured": structured, "judged_at": <ISO now>})`
        called **unconditionally**, on the send branch AND the skip branch, before the
        branch-specific write. This is D-05's inversion: the Hub's `/api/today` needs the
        day summary whether or not Klaus spoke.
      - Branch-specific:
        - send → `{"status": "sent", "trigger": trigger, "sent_at": <ISO now>,
          "composed_via": decision["composed_via"]}`
        - judgment skip → `{"status": "skipped_by_judgment", "trigger": trigger,
          "skip_cause": decision["skip_cause"]}` and **no** `composed_via` key at all
          (absent means "no compose was attempted" — Pitfall 3's three-valued distinction).

    **Infra failure stays a send.** On the legacy (flag-off) branch, thread the compose
    outcome into `composed_via`: `"llm"` when the primary or Gemini-fallback compose
    produced the text, `"plain_text_fallback"` when `_plain_text_fallback` produced it.
    `_compose_nightly` currently returns only the text — have it return, or record via a
    module-level marker it already sets, which tier produced the message; the minimal change
    is to give `_compose_nightly` a second return value or an out-parameter dict and update
    its two call sites. SC-1 is unsatisfiable without this field: a total infra failure must
    still SEND (status `sent`) while being greppable as degraded.

    **Terminal idempotency (D-04/D-12).** Change `was_sent` to return True when
    `_get_state(target_date).get("status")` is in `{"sent", "skipped_by_judgment"}`. Keep the
    function name — `/trigger/nightly` and the backstop both call it — but update its
    docstring to say "terminal", not "sent". The 01:00 backstop therefore gets fresh
    judgment only on nights where nothing ran at all, and never re-litigates a night Klaus
    already decided to stay quiet on.

    **D-06 note.** The nightly does not own `daily_note` (that is the morning's field, plan
    33-07). Do not write `daily_note` here. Do record `decision["draft"]` in the skip-branch
    state write under a `draft` key so `get_recent_decisions` (plan 33-09) and the heartbeat
    have Klaus's own one-liner for the night he chose not to speak.
  </action>
