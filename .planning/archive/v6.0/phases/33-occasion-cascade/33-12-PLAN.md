<objective>
Make the new surfaces deployable and get the morning trigger genuinely live.

Everything through plan 33-11 is code. This plan is configuration, documentation and the
one hard human prerequisite the phase cannot fake: Amit has to build the Sleep-Focus-*off*
iOS automation. D-31's sequencing is strict and exists to prevent a silent-morning gap —
(1) `/trigger/morning` deploys dark, (2) Amit builds and enables the Shortcut, (3) real
triggers are confirmed landing, (4) only then does `morning-briefing-tick` retire. Step (4)
is plan 33-13; this plan delivers (1)-(3).

not listed in `deploy.yml` is wiped from the Cloud Run config on the next deploy, so
`OCCASION_CASCADE` and the `MORNING_TRIGGER_TOKEN` secret mount must be declared there and
not set out of band.

and a confirmed live trigger.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Secret Manager → Cloud Run env → `_verify_morning_trigger_request` | The bearer secret's confidentiality is the only thing standing between the public internet and Klaus messaging Amit |
| iPhone Shortcut storage → the bearer token in an automation definition | The token is stored on the device in plaintext within the automation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-01c | Spoofing | `MORNING_TRIGGER_TOKEN` provisioning | mitigate | The secret is generated fresh (`openssl rand -base64 32`) and stored only in Secret Manager and the iOS automation; it is a **distinct** value from `NIGHTLY_TRIGGER_TOKEN` (D-13), so compromise of one proactive surface does not unlock the other |
| T-33-39 | Information Disclosure | secret value in CI/deploy config | mitigate | `deploy.yml` references `klaus-morning-trigger-token:latest` via `--update-secrets`; the value never appears in the workflow file, the repo, or the build logs |
| T-33-40 | Elevation of Privilege | env-var clobber removing the secret mount | mitigate | Both `OCCASION_CASCADE` and the secret mount are declared in `deploy.yml` rather than set out of band, so the documented `--set-env-vars` clobber (Phase 29 web-push incident) cannot silently unmount them. With the secret absent the route refuses all requests (HTTP 500), so the failure mode is closed, not open |
| T-33-41 | Denial of Service | premature retirement of `morning-briefing-tick` | mitigate | The blocking human checkpoint gates plan 33-13 on a confirmed live trigger; `docs/DEPLOYMENT.md` § 19 keeps the job listed with an explicit retirement-point note |
| T-33-SC | Tampering | npm/pip/cargo installs | accept | No packages installed in this phase (33-RESEARCH.md § Standard Stack) |
</threat_model>
