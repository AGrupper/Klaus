<objective>
Make the rollout watchable.

D-28 pairs two instruments: `get_recent_decisions` (plan 33-09) for Amit to ask, and the
hourly heartbeat for the things nobody thinks to ask about. This plan builds the second.

The design constraint from 33-RESEARCH § Pitfall 8 is load-bearing: `_log_cron_run`'s `ok`
boolean was designed for crash detection, not judgment-quality detection. An occasion that
silently fell through to its deterministic plain-text fallback still returns normally and
still gets logged `ok=True`, which would mask a real degradation from the existing
`check_cron_health` checker. So these four checks read each occasion's **own state doc** —
the `status` / `composed_via` / `skip_cause` fields plans 33-06/07/08 write — not the
generic `heartbeat_runs` ledger.

The mirror-image requirement is just as important: a legitimate `skipped_by_judgment` must
NOT trip a staleness alert, or the phase's central feature becomes a permanent false alarm.

Purpose: OCC-06's observability half, and the SC-1 guarantee that a failure-skip can never
pass as a judgment-skip in production.
Output: `check_occasion_health()` emitting the four D-28 anomaly classes as `Signal`s.
</objective>
